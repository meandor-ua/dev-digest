# Routing table and deterministic convention checks

Kept out of SKILL.md because this is the part that churns as packages, skills,
or conventions are added.

## Path -> skill routing

Match a changed file's path top-to-bottom; a file can land in more than one
row (e.g. a `server/**/routes.ts` file gets both its module row and the
`routes.ts` row). A file matching no row still gets the catch-all
`typescript-expert` row if it is TypeScript.

| Path pattern | Bucket | Skills to load |
|---|---|---|
| `client/**` | client | `frontend-architecture`, `react-best-practices`, `next-best-practices` |
| `client/**/*.test.tsx`, `client/**/*.test.ts` | client | + `react-testing-library` |
| `server/src/modules/**`, `server/src/adapters/**`, `server/src/platform/**` | server | `onion-architecture`, `fastify-best-practices` |
| `server/**/routes.ts` | server | + `zod` |
| `server/src/db/schema/**`, `server/src/db/migrations/**` | server | `drizzle-orm-patterns`, `postgresql-table-design` |
| `reviewer-core/**` | reviewer-core AND server | `onion-architecture` (purity rule only), `zod`, `typescript-expert` |
| `e2e/specs/*.flow.json` | e2e | convention check only, no review skill fits JSON flow files |
| `e2e/**/*.ts` | e2e | `typescript-expert` (advisory tier only) |
| any `*.ts`/`*.tsx` not otherwise matched | shared | `typescript-expert` (advisory tier only) |
| auth, session, input validation, file upload, secrets, new endpoint in any package | (its bucket) | + `security` |

**Cross-package edge to preserve:** a `reviewer-core/**`-only change must
still open the **server** bucket, even though no `server/` file changed.
`server/tsconfig.json:24-25` aliases `@devdigest/reviewer-core` straight to
`../reviewer-core/src`, so a reviewer-core change is type-checked as part of
`server`'s own `pnpm typecheck`, and a break there only surfaces there. Route
`reviewer-core/**` changes to both buckets rather than only its own.

## Deterministic convention checks (git-only, no toolchain)

Run these against the resolved change-set before any subagent is launched.
None needs LLM judgement. Each one names its own tier below — some are
blockers, several are should-fix; don't promote a should-fix to a blocker
just because it was found deterministically.

- **Applied migration touched.** Any changed path under
  `server/src/db/migrations/` -> blocker. Migrations are add-only; a diff
  inside an existing migration file means one already applied is being
  hand-edited.
- **Vendor copy edited on one side only.** AGENTS.md requires
  `server/src/vendor/**` and `client/src/vendor/**` to be hand-edited in
  lockstep. Check this **per changed file, not by diffing the trees**:
  for each changed path under one package's `vendor/`, require the mirrored
  path under the other package's `vendor/` to be in the same change-set ->
  blocker if only one side moved.

  Do **not** run `diff -r` over the two vendor trees and blocker on any
  mismatch. Two reasons it would fire on every run:
  `client/src/vendor/ui` has no server counterpart at all, and the shared
  subtrees are already divergent on `main` (the server copy is a superset --
  `shared/adapters.ts` and four `shared/contracts/*.ts` files differ today).
  That drift is pre-existing, so under the severity rubric it is at
  most a `should-fix` labelled pre-existing, never a blocker on someone whose
  diff merely touched the file.
- **Lockfile or skills-lock.json touched.** Any of `client/pnpm-lock.yaml`,
  `server/pnpm-lock.yaml`, `reviewer-core/package-lock.json`,
  `e2e/package-lock.json`, or `skills-lock.json` in the diff -> blocker
  unless it was regenerated by that package's own package manager (check the
  diff is a full regenerate, not a hand-edited line).
- **Import extension convention.** In `server/`, `reviewer-core/`, `e2e/`:
  a new or changed relative import missing the `.js` extension on a `.ts`
  source -> should-fix (the one exception is the `server/src/db/schema*`
  barrel). In `client/`: a relative import carrying an extension -> should-fix.
- **Server test naming.** A new test file under `server/` that touches a
  repository or does real I/O but is named `*.test.ts` instead of
  `*.it.test.ts` (or the reverse: a pure unit test wrongly suffixed
  `*.it.test.ts`) -> should-fix.
- **Missing co-located client test.** A new directory under
  `client/**/_components/<Name>/` with a `<Name>.tsx` but no `<Name>.test.tsx`
  -> should-fix.
- **Schema/migration file hand-restructured.** A changed file under
  `server/src/db/schema/*` that looks like a rename/restructure rather than an
  additive new domain file -> should-fix, flag for manual confirmation.
